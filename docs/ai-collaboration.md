# 🤖 AI 协作开发手册 —— 指挥 AI 做 WebGIS

> 你的角色：**架构师 + 产品经理**（定需求、选技术、验收结果）
> AI 的角色：**工程师**（写代码、修 bug、优化）
> 你不需要会写代码，但需要会三件事：**选型、提需求、验收**。

---

## 一、WebGIS 能力地图：什么需求 → 用什么库

### 按需求场景选型

| 你想要的效果 | 首选方案 | 备选 | 说明 |
|---|---|---|---|
| 普通二维地图、标记、弹窗 | **Leaflet** | OpenLayers | 简单够用，生态最大 |
| 漂亮的现代地图、自定义配色 | **MapLibre GL** + 免费样式 | Mapbox GL | 矢量渲染，样式自由 |
| 倾斜看建筑、3D 城市 | **MapLibre GL** (fill-extrusion) | Cesium | MapLibre 轻量得多 |
| 真三维地球、飞行视角 | **CesiumJS** | — | 数字孪生标配 |
| 画图、圈选、标绘 | **Leaflet-Geoman** | leaflet-draw | 前者更好维护 |
| 距离/面积/缓冲区计算 | **turf.js** | PostGIS（后端） | 数据大就上后端 |
| 海量点（上万个）闪烁动画 | **deck.gl** / Leaflet.heat | MapLibre 表达式 | 超过 1 万点必换 WebGL 方案 |
| 热力图 | Leaflet.heat | MapLibre / deck.gl | — |
| 轨迹回放、动态目标 | Cesium + CZML | MapLibre + requestAnimationFrame | 三维用前者 |
| 地形/山体阴影 | MapLibre raster-dem | Cesium World Terrain | — |
| 行政区边界数据 | 阿里 DataV GeoAtlas | 天地图 | 免费，全国到区县 |
| 底图（国内合规） | 天地图（需申请key） | 高德（注意GCJ-02） | OSM 国内访问不稳 |

### 问 AI 选型时的正确姿势

❌ 差：「帮我做个地图」
✅ 好：「我要在网页上展示 5000 个传感器点位，缩放时要有聚合效果，点击看详情，用哪个库最合适？为什么不用另外两个？」

## 二、需求描述模板（直接复制填空）

给 AI 提 WebGIS 需求时，按这 9 项说清楚，一次成功率提升 90%：

```markdown
1. 【目标】一句话说清给谁用、干什么
   例：给我个人用的家乡美食探店地图

2. 【底图】用什么底图？
   例：OpenStreetMap / 天地图 / 暗色风格

3. 【数据】数据是什么、多少量、什么格式、坐标系统？
   例：约 300 个点，GeoJSON，WGS-84 经纬度
   ⚠️ 国内高德/腾讯数据是 GCJ-02，必须说明，否则偏移几百米

4. 【交互】用户能做什么操作？
   例：点击弹窗看详情、按分类筛选、搜索定位

5. 【样式】有什么视觉要求？
   例：不同分类不同颜色、选中高亮、暗色 UI

6. 【运行环境】单 HTML 文件？还是要部署的完整项目？
   例：单文件双击就能打开（CDN 引入）

7. 【约束】
   例：无需后端、无需 API key、手机上也能看

8. 【边界情况】
   例：数据加载失败的提示、无数据时的空状态

9. 【验收标准】怎么算做完？
   例：手机浏览器打开 3 秒内可见地图，点击标记 200ms 内弹窗
```

### 需求描述的黄金法则

- **说"什么"和"为什么"，不说"怎么做"**——实现方案让 AI 出，你从 2~3 个方案里挑
- **给样例数据结构**——贴 3 行真实数据胜过 100 字描述
- **先要方案再要代码**——「先给我 2 个实现方案和利弊，不要写代码」
- **一次一个功能**——小步交付，每步可验收，避免 AI 一次写一大坨没法查

## 三、验收清单（AI 交付后逐项检查）

### 功能验收
- [ ] 所有交互按需求工作（每个按钮、点击、筛选都亲手点一遍）
- [ ] 边界情况：空数据、网络失败、极端缩放级别不崩
- [ ] 手机/不同浏览器打开正常

### GIS 专业验收（你的强项，AI 最容易错的地方）
- [ ] **坐标系**：点位有没有偏移？（国内经典坑：WGS-84 数据叠了 GCJ-02 底图）
- [ ] **坐标顺序**：[lng,lat] vs [lat,lng]，位置跑到海里/镜像位置必查这个
- [ ] 底图版权声明（attribution）保留了吗（法律合规）
- [ ] 缩放到最大/最小时瓦片是否正常、有无越界报错
- [ ] 面积/距离单位是否正确（平方米 vs 平方公里，大圆 vs 平面距离）

### 工程验收（让 AI 自己过一遍）
把这段发给 AI：
> 请自查以下项目并逐条报告：1) 代码有无冗余或未使用的变量 2) 有无内存泄漏风险（事件监听未清理、定时器未清除）3) 错误处理是否完整 4) 在弱网环境会怎样 5) 如果数据量变为 10 倍会出现什么问题

## 四、高效沟通技巧（实战总结）

| 场景 | 你说什么 | 效果 |
|---|---|---|
| AI 写错了 | 「点位整体向东北偏了约 300 米，检查坐标系和坐标顺序」 | 比「不对，重来」快 10 倍 |
| 想优化 | 「现在 1 万个点会卡，给我 2 个优化方案，说明各自的性能预期」 | 获得 + 教育 |
| 想学习 | 「用 3 句话解释刚才修改的关键点，别贴代码」 | 积累选型知识 |
| 方案选择 | 「列出利弊让我决策，我不懂实现细节」 | 保持你的架构师角色 |
| 保存进度 | 「把当前版本提交到 git」 | 随时可回滚，不怕改坏 |

## 五、学习循环（每周节奏）

```
你提需求（用模板）
   ↓
AI 出方案 → 你拍板
   ↓
AI 实现 → 你按清单验收
   ↓
发现问题 → 精准反馈 → 迭代
   ↓
AI 用 3 句话讲解本次关键决策 → 你沉淀为选型知识
   ↓
提交 git，更新进度看板
```

**记住：验收发现的问题越具体，你的 GIS 专业判断就越值钱。AI 写代码很快，但"这个点偏了 300 米"这种判断，只有你能做。**
